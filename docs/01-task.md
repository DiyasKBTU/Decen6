# Задача и требования простыми словами

Документ для тех, кто впервые видит кейс. Технических знаний не нужно.

## Кто заказчик и в чём боль

**Grand Mobile** — мобильная ролевая игра (как GTA RP): игроки живут в городе, работают, вступают во фракции и семьи, могут быть полицейскими или бандитами. Больше 500 тысяч игроков в день, серверы в СНГ, Казахстане, Узбекистане и других странах, 6 языков.

Игроки постоянно пишут администраторам:

- **жалоба** — из лаунчера (программа запуска игры): «игрок X меня оскорбил», со скриншотами и номером пункта правил;
- **репорт** — короткое сообщение прямо из игры: «помогите», «застрял в текстурах», «меня убивают у спавна».

Админы отвечают вручную, и большинство ответов однотипные. Серьёзное (взлом аккаунта, не пришёл платёж) теряется среди сотен «помогите».

## Что от нас хотят

Сервис-помощник для админа. Он **ничего не делает сам** (не наказывает, не разбанивает), а для каждого обращения:

1. определяет язык;
2. определяет **категорию** (что за проблема) и **приоритет** (насколько срочно);
3. отсеивает спам и дубли;
4. достаёт факты: на кого жалуются, какой пункт правил назван, есть ли доказательства;
5. пишет **черновик ответа** на языке игрока со ссылками на настоящие пункты правил;
6. говорит, можно ли отправить ответ сразу или **нужен человек**, и почему.

## Что сдаём

- **HTTP-сервис** `POST /triage`: получает обращение, возвращает разбор в формате JSON (описан ниже).
- **Команду** `make predict IN=tickets.jsonl OUT=pred.jsonl`: прогоняет целый файл. Через неё организаторы проверят скрытые 500 обращений.
- **Отчёт**: метрики на проверочных данных, примеры черновиков, доля «нужен человек», стоимость одного обращения, скорость.

### Ответ сервиса по полям

| Поле | Что это | Пример |
|---|---|---|
| `lang` | язык текста игрока | `ru` |
| `category` | категория из списка заказчика (14 штук) | `complaint.insult` — оскорбления |
| `priority` | срочность: p0 — критично … p3 — низкая | `p2` |
| `is_spam_or_duplicate` | спам или повтор | `false` |
| `extracted` | факты: ник обвиняемого, названные пункты, есть ли доказательства, сервер | `{"nickname": "Arman_Petrov", ...}` |
| `draft_reply` | черновик: язык, текст, на какие пункты правил ссылается (`cited`) | `"cited": ["2.1"]` |
| `needs_human` | нужен ли человек | `true` |
| `confidence` | уверенность сервиса, 0–1 | `0.82` |
| `reasons` | почему так решили | `["решение о наказании подтверждает администратор"]` |

## Как оценивают

| Критерий | Вес | Простыми словами |
|---|---|---|
| Классификация | 25% | Насколько верно угаданы категория (accuracy) и приоритет (macro-F1, см. словарь) на скрытых 500 обращениях |
| Качество черновиков | 30% | Админы Grand Mobile вслепую ставят оценку 1–5 сотне наших черновиков, сравнивая с настоящим ответом |
| Без галлюцинаций | 20% | Каждая ссылка на правило должна существовать и подходить по смыслу. **Один выдуманный пункт обнуляет обращение** |
| Казахский и узбекский | 15% | Носители языка оценивают черновики на kk и uz |
| Цена и скорость | 10% | Не дороже $0,002 за обращение (или своя модель), 95% ответов быстрее 5 секунд |

Ещё есть **бонусы** (без готового основного решения не оцениваются): склейка дублей, автоматическое предложение новых шаблонов ответов, интерфейс админа с кнопками «отправить», «править», «эскалировать» и сохранением правок.

## Жёсткие ограничения

1. **RAG по правилам и базе знаний обязателен.** Перед ответом система должна найти нужные пункты правил и опереться на них. Ответ без ссылок допустим только там, где правила не нужны (например, «уточните вопрос»).
2. **Черновик не обещает** разбан, возврат денег или имущества, наказание другого игрока. Если такая тема есть — `needs_human: true`.
3. **Платежи, апелляции на баны и подозрения на взлом всегда идут человеку.**

## Подводные камни в данных

- Тексты короткие, с опечатками, сленгом и смесью языков: «оск родни», «дм в зз», «2.1оп».
- Игра работает в старой кодировке cp1251, поэтому на казахских серверах буквы заменены похожими: `ќ` вместо `қ`, `ѕ` вместо `ң` и так далее.
- Игроки преувеличивают и путают пункты правил. Факты из текста — это версия игрока, а не правда.
- Скриншотов нет, есть только их количество.

## Правила обращения с данными (важно)

- Данные только для хакатона. **Нельзя публиковать их и класть в репозиторий**, даже кусками. В нашем проекте это закрыто файлом `.gitignore`: данные, построенные из них файлы (`artifacts/`) и результаты прогонов (`out/`) в git не попадают.
- Нельзя пытаться узнать, кто есть кто (данные обезличены).
- Удалить данные в течение 14 дней после объявления победителей.

## Словарь

| Слово | Значение |
|---|---|
| Триаж | Сортировка обращений: что это, насколько срочно, кому отдать |
| Черновик | Предлагаемый ответ, который админ отправит как есть или поправит |
| RAG | «Поиск, потом ответ»: система сначала находит нужные пункты правил и похожие прошлые ответы, а потом пишет ответ только на их основе |
| LLM | Большая языковая модель (как ChatGPT или Claude), которая умеет писать тексты |
| Галлюцинация | Когда модель уверенно выдумывает то, чего нет (например, несуществующий пункт правил) |
| `needs_human` | «Нужен человек» — ответ нельзя отправлять без проверки админом |
| p0 / p1 / p2 / p3 | Приоритет: p0 — взлом, платёж, угрозы; p1 — читы, мошенничество, реклама; p2 — оскорбления, DM; p3 — вопросы, оффтоп, пустые жалобы |
| train / valid / hidden | Обучающие данные / данные для проверки / скрытый тест организаторов |
| Accuracy | Доля верно угаданных ответов |
| Macro-F1 | Средняя точность по классам, где каждый класс весит одинаково: нельзя хорошо угадывать частое и проваливать редкое |
| p95 | Время, в которое укладываются 95% ответов |
| DM, DB, SK, TK | Игровые термины: убийство без причины, с машины, на месте появления, своего |
| ЗЗ / GZ | Зелёная зона — место, где нельзя убивать |
